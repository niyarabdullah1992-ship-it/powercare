### A1. عزل المستأجر (غير قابل للتفاوض)

موجود جزئيًا: `CompanyAccount`, `CompanySession`, `Employee`, `Station`,

### A2. مخطط البيانات (حد أدنى للمهام)

## المرحلة B — المهام والعمليات (قسم واحد كامل)

مرجع المنطق: `class Component` في Platform حول Operations / Task detail  
(تقريبًا من محاور `PLANS`/`KINDS`/`horizonFor` وبطاقة المهمة و`points`).

### B1. معادلات يجب أن تعيش على الخادم

**نقاط المهمة (تُمنح عند اعتماد المشرف فقط، لا عند تسجيل الإنجاز):**

```
priorityValue = High→3 | Medium→2 | Low→1
points = priorityValue × effortWeight   // effortWeight ∈ [1..5]
```

ملاحظة: `supabaseTargets` اليوم يستخدم مقياسًا أكبر (100/75/…).  
**وحّد المعادلة مع التصميم أعلاه** في مسار الاعتماد و`PointsLedger`،  
ولا تترك مسارين يعطيان قيمتين مختلفتين لنفس المهمة.

**أفق الخطة (مشتق من تاريخ الاستحقاق ما لم يُثبَّت يدويًا):**

```
daysUntilDue = dueDate − today   // أجزاء تاريخ محلية، لا toISOString() لليوم
horizon = days ≤ 7 → w
        | ≤ 31 → m
        | ≤ 92 → q
        | ≤ 183 → h
        | else → y
```

الخطة أفق زمني لا مجلد — المهمة تظهر في قائمتها وفي مجموعتها دون نسخ سجلين.

**عدّادات العمليات (من الصفوف بعد فلتر النطاق):**

```
done     = progress === 100%
overdue  = due < today
today    = due === today
awaiting = completedCount ≥ targetCount && not yet approved
active   = totalInScope − done
badge    = overdue + awaiting
```

**إنجاز مجموعة الأفق:**

```
unitsDone / unitsTarget عبر صفوف الأفق → pct
```

**وزن الجهد المقترح من المسمى (المدير قد يتجاوزه قبل البدء):**  
نفس قواعد العناوين في النموذج / `suggestEffortWeight` إن وُجدت في `src/lib`.

**بوابة الشهادة (تُسمّي السبب — لا تعطيل صامت):**

```
CERT_FOR: pm→loto, cm→loto, em→fa, pr→wah, cp→null
```

إن انتهت شهادة المطلوب لأي مُسند (فرد / مجموعة / كامل المحطة) → رفض الإسناد  
برسالة تذكر الشهادة والأسماء.

**تسجيل الإنجاز:** لا يُقبل بلا أثر (مرفق أو إفادة).  
عند اكتمال العدد → حالة «بانتظار الاعتماد».  
الاعتماد → كتابة `PointsLedger` + إقفال الأمر.  
الرفض بسبب → إعادة للمنفّذ مع طلب إثبات.

**محوران مغلقان فقط:** `planHorizon` + `workKind` (pm/cm/em/pr/cp).  
الباقي فلاتر.

### B2. API مقترح (أسماء وفق أسلوب المشروع)

عبر توسيع `supabaseTargets` أو دالة `operations` واحدة، كلها بعد `authPowerCareSession`:

- `list` / `create` / `get` / `update`
- `logCompletion` (بوابة الإثبات)
- `approveCompletion` / `rejectCompletion`
- `counts` مشتقة من نفس استعلام القائمة + النطاق

كل إجراء → `AuditLog`.

### B3. الواجهة بعد ثبات الـ API فقط

أعد بناء شاشة العمليات في React (`src/pages` + `src/components/...`)  
من نفس السلوك، لا من لصق HTML.  
النطاق في الهيدر يصفّي كل القوائم. RTL عربي أولًا عبر `useI18n`.
